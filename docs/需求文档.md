# OfferLab 需求文档（v1.2）

> 用一句话说清：**把简历和岗位 JD 逐条对照，按"证据强度"打分并给出可执行的修改建议。**
> 本文档回答三个问题：给谁做、做什么、做到什么程度算完成。

## 1. 背景与问题

求职者最常做的两件事恰好都没用：

1. 把 JD 里的词全塞进简历（关键词堆砌）——招聘系统过了，面试一问就露；
2. 一份简历投 100 个岗位——自己都说不清匹配度。

现有工具（简历打分网站）大多只做关键词命中计数，**不区分"列了个名字"和"项目里真做过"**，结论也无法解释。

## 2. 目标用户与场景

| 用户 | 场景 | 诉求 |
|---|---|---|
| 应届/实习生（主） | 投递前自查 | 我这份简历够不够、差在哪、怎么改 |
| 转行者 | 换方向前评估 | 目标岗位的硬性要求我缺几项 |
| 在校生 | 选学习方向 | 本地岗位到底要什么技能 |

**核心场景**：上传简历 → 选一个目标 JD → 30 秒内看到"证据分 + 四档分级 + 缺口建议"。

## 4. 页面结构

```
/            门面：定位、三步说明、3D 视觉（Blender 生成 glTF）
/analyze     主流程：上传简历 → 选 JD → 报告 → 流式建议 → 模拟面试
/jobs        技能词频：按「出现次数 → 硬性占比」排序
/dashboard   校招岗位数据看板：类型分布 / 薪资对比 / 招聘人数 Top8 / 地区分布
/api/resume  文件 → 纯文本（仅内存）
/api/advise  改写建议（SSE 流式，无 Key 走规则版）
/api/interview 模拟面试（SSE 流式）
```

## 5. 数据契约（关键，面试会问）

**JdRequirement**：`{ skill, weight: 1|2|3, must: boolean }`

**MatchReport**：
```
score        0-100 加权证据分
mustHit/mustTotal   硬性要求命中数
findings[]   每条技能：level(0-3)、weight、must、evidence[]（原文片段）
gaps/weak/mid/strengths   按 level 分组的四档
parseStats   字符数 / 识别技能数 / 项目段行数
```

**打分的硬约束**：同一简历 + 同一 JD，**结果必须逐字一致**。这是产品可信度的地基，也是契约测试里最先验证的一条。

## 6. 技术选型与理由

| 选择 | 理由 |
|---|---|
| Next.js 16 App Router | 前后端一体，7 条路由 + SSE 都在一个仓库里，部署面小 |
| 打分用规则、不用 LLM | 打分必须可复现、可解释；LLM 只做"把结论讲成人话" |
| 服务端重算报告 | 接口只收「简历 + JD」，防止前端伪造分数 |
| 手写 SSE 解析 | 不引 SDK，能处理半包、`[DONE]`、HTTP 200 但流内 error |
| unpdf | 服务端 PDF 抽文本，无系统依赖，Vercel/Docker 都能跑 |
| Blender 生成 glTF | 门面资产体积可控（86KB），不把重实时渲染搬进浏览器 |
| ECharts | 看板 4 张图，按需引入，不引 React 图表封装 |

## 7. 非功能需求

- **性能**：报告生成 < 200ms（纯计算）；首屏 JS 不含 pdf 解析；3D 顶点 < 3k 保核显 60fps。
- **可靠性**：LLM 挂了 → 规则版；检索不到 → 不编造；PDF 损坏 → 明确报错而不是空报告。
- **安全**：简历不落盘；令牌鉴权 + 限流（resume 10/min、advise 20/min、interview 30/min）。
- **可维护**：词表/样例/用例都是数据文件，改数据不改代码。

## 8. 验收标准（Definition of Done）

1. `npm run build` 通过，`npm test` 11 条引擎断言全绿；
2. `pytest tests/api` 26 条接口用例全绿；
3. 打开 `/analyze` 走完「载入示例简历 → 选 JD → 出报告 → 生成建议 → 开始面试」全流程；
4. 同输入两次打分完全一致（契约测试覆盖）；
5. `/dashboard` 四张图渲染正常，且数字与 Excel 原始数据一致。

## 9. 已知限制（诚实清单）

- 内置 JD 是 8 条**人工精编样例**，不是爬取数据；真实岗位请用「粘贴 JD」。
- 扫描件/图片型简历不支持（需 OCR）。
- 词表 47 项，词表外技能不参与打分（宁缺毋滥，避免无法解释的分数）。
- 限流计数在进程内存，多实例部署不精确（要精确需 Redis）。
- 校招看板里"其他"类占比较高，因为原始 Excel 只给了部分岗位明细。
